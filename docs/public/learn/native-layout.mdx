---
title: "Native layout and Cinnamon"
description: "How Flex, Grid, CSS geometry and native rendering relate."
---

**Cinnamon** is the layout engine *inside PSX*. It calculates renderer-neutral geometry before native controls receive their rectangles. The primary engine is Rust; Python provides a fallback. Both engines are verified explicitly in native integration CI.

```python
from velto.ui import psx

view = psx("""
    <Flex direction="column" gap="12px">
        <Text value="First" />
        <Text value="Second" />
    </Flex>
""")
```

The window size comes from Qyro project settings and supplies constraints for layout. `Flex` and `Grid` have real geometric effects; a headless renderer without proper viewport constraints may reject geometry-bearing layouts.

## Styling and geometry

CSS-like properties are handled by PSX; Cinnamon resolves supported sizes, margins, padding and layout arrangements. Backend-native widgets are responsible for the final appearance and interaction, not their own independent competing layout calculations.

See [CSS and the box model](/guide/styling) and [supported backends](/guide/compatibility). Some web concepts, such as arbitrary browser floats or full browser fragmentation, are not promised by this engine.

**Verify:** [native Qyro integration, six combinations](https://github.com/Neuri-AI/Velto/actions/runs/39962860498) asserts committed geometry using real Cinnamon Rust and Python engines.
