Velto supports component-local state through **`use_state`** and shared application state through **Pydux**.

## Local state

```python
from velto.ui import component, Text, Button, use_state, Fragment

@component
def Counter():
    count, set_count = use_state(0)
    return Fragment(
        Text(f"Count: {count}"),
        Button("Increment", on_click=lambda: set_count(count + 1)),
    )
```

The example is a component fragment. Hooks are called during render and must remain in a stable order. Do not conditionally call them.

## Shared state with Pydux

The following pattern was exercised by the installed cross-package certification:

```python
from velto import VeltoContext
from velto.ui import psx
from velto.state import Action, Store, use_selector

def reducer(state, action):
    if action.type == "increment":
        return {"count": state["count"] + 1}
    return state

store = Store(reducer, {"count": 0})

class CounterApp(VeltoContext):
    pydux_store = store

    def render(self):
        count = use_selector(lambda state: state["count"])
        return psx('<Text value={label} />', scope={"label": str(count)})

store.dispatch(Action("increment"))
```

As with any application, the class needs its project settings and a real mount/run lifecycle before updates can reach native controls. The certification verifies selector rerender and provider cleanup after unmount. See [integration evidence](https://github.com/Neuri-AI/Velto/actions/runs/39962860498).

For event-driven changes, dispatch an action from your callback rather than during the render itself.
