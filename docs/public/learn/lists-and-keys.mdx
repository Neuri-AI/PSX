---
title: "Lists and keys"
description: "Keep identity stable when repeated children change order."
---

Use a stable `key` for each sibling child in a dynamic list. Prefer data IDs rather than list indexes if items can be inserted, removed or reordered. Duplicate sibling keys are rejected.

```python
from velto.ui import Fragment, Text

tasks = [{"id": "a", "label": "Plan"}, {"id": "b", "label": "Build"}]
view = Fragment(*(Text(t["label"], key=t["id"]) for t in tasks))
```

This is an **unmounted VNode fragment**. It demonstrates the identity contract, not a complete application. Changes in keys may cause remounts; stable keys help the reconciler preserve eligible native widgets and component state.

See [components](/learn/components), [state](/learn/state-and-events) and [Hot Reload](/guide/hot-reload). Check identity behavior on your chosen native toolkit.
