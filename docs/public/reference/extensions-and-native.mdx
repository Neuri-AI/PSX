The `velto.ui` facade re-exports original PSX extension interfaces without identity-changing wrappers. Advanced symbols include `ComponentRegistry`, `ComponentDefinition`, `register_component`, `RendererAdapterRegistry`, `register_adapter`, `ComponentAdapter`, `Plugin`, `PluginAPI`, `load_plugins`, `Native`, `NativeWidget` and `NativeOwnership`.

## Registering a component

Custom components usually begin with `@component`; advanced registration is for extending the reusable registry. A registry entry identifies an operation the renderer might be able to mount, not a proof of native support.

## Native widget ownership

`Native` is the extension boundary for toolkit-native controls. It must be used with a matching backend and ownership policy; external Qt widgets, such as pyqtgraph plots, are not interchangeable with Kivy or Tkinter objects. The renderer owns UI updates and Cinnamon remains responsible for geometric layout.

## Plugins and adapters

Plugins and renderer adapters are integration points for advanced library authors. Do not bypass reconciliation or create a parallel layout engine. Use the [generated public contracts](/reference/generated-contracts) and the [native capability matrix](/reference/native-css-capabilities) for signature and support details.

**Validation scope:** [installed native app integration](https://github.com/Neuri-AI/Velto/actions/runs/39962860498) covers PySide6, Tkinter and Kivy applications; an embedded third-party widget requires additional toolkit-specific execution evidence. See [native integration guide](/guide/native-integration).
