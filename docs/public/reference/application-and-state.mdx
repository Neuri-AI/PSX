## The application entry point

```python
from velto import VeltoContext
from velto.ui import psx

class Example(VeltoContext):
    def render(self):
        return psx('<Text value="Hello" />')
```

`VeltoContext` is the **Qyro Engine** class exposed through the facade, not a new wrapper. Application settings such as `framework` and `window` are read from project configuration. Run from a valid project using `velto start` or use the documented `VeltoContext` lifecycle. There is no `<Window>` markup element.

## PSX components and hooks

The `velto.ui` module re-exports `App`, `psx`, `component`, `VNode`, `use_state`, `use_effect` and `use_ref`. Components must call hooks in the same order on each render. `use_state` returns a state value and a setter; `use_effect` can return cleanup work; `use_ref` retains a reference.

PSX Markup accepts quoted literal attributes and supported expressions. The verified installed integration test exercises explicit scope with `psx(..., scope={"label": "..."})`. Do **not** rely on `eval` or an obsolete separate `psx.markup.transform` command. A VNode expression fragment alone does not initialize a native window.

## Shared state

The `velto.state` facade directly exports Pydux `Action`, `Store`, `StoreProvider`, `configure_store`, `create_slice`, `use_dispatch` and `use_selector`. On a `VeltoContext` subclass, the validated integration uses a `pydux_store` and `use_selector`; dispatching an `Action` causes an eligible rerender and the provider is cleaned up on unmount.

See [state with a real reducer](/learn/state-and-events), the [actual cross-package integration test](https://github.com/Neuri-AI/Velto/blob/main/tests/test_installed_runtime_integration.py) and [its passing six-way native CI](https://github.com/Neuri-AI/Velto/actions/runs/39962860498).

## Boundaries

The PSX `App` interface is lower-level than `VeltoContext`. If building a custom embedding or renderer, consult the [generated PSX signatures](/reference/generated-contracts). Native lifecycle, renderer selection and widget ownership must match your actual backend.
