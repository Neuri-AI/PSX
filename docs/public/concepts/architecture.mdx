---
title: "Architecture"
description: "The division of work between the Velto subsystems."
---

```text
Python application + PSX Markup
          |
     VeltoContext (Qyro Engine)
          |
      PSX: VNodes, components, hooks, reconciler
          |               \
          |             Pydux state/selectors
          |
      Cinnamon (inside PSX)
      Rust primary / Python fallback
          |
      Native renderer adapter
          |
    PySide6 / PyQt / Tkinter / Kivy
```

Qyro Engine handles application configuration, resource lookup and lifecycle; it does not replace PSX's reconciler. Cinnamon computes renderer-neutral layout inside PSX and must not be bypassed by adapters. Pydux owns store and selector responsibilities rather than native widget construction. Velto CLI orchestrates scaffold/start/restart/build/distribution outside this rendering path.

The `velto` facade is an API entry point, not a duplicate state store or runtime.

**Evidence:** the [real installed application suite](https://github.com/Neuri-AI/Velto/actions/runs/39962860498) runs the central stack with both Cinnamon engines. Frozen resources have a separate [distribution receipt](https://github.com/Neuri-AI/Velto/actions/runs/39967824985).
