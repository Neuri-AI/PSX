---
title: "How Velto works"
description: "Follow PSX Markup from Python source to native widgets."
---

When your application runs, **Qyro Engine** initializes `VeltoContext` with the project's settings and resource paths. Your `render()` returns **PSX Markup**. PSX produces virtual nodes (VNodes), reconciles state changes and coordinates its native renderer.

**Cinnamon lives within PSX** and computes box geometry in a renderer-neutral way. Rust is the primary engine, with Python fallback. The selected renderer creates native Qt, Tkinter or Kivy widgets. **Pydux** can supply shared state; components subscribe using selectors and rerender on dispatched actions.

**Velto CLI** handles project initialization, development startup, frozen builds and bundling. The public `velto` facade re-exports the actual objects of Qyro, PSX and Pydux rather than wrappers.

This architecture does not ship a browser HTML DOM or a second, competing native layout engine.

**Verification:** [end-to-end mounted application](https://github.com/Neuri-AI/Velto/actions/runs/39962860498) uses Qyro settings, PSX Markup, Pydux selectors and both Cinnamon implementations, then releases the native handle on unmount.
