Welcome! In this guide, you'll go from a fresh Python environment to your first working Velto application.

You don't need to know Qt, Tkinter, Kivy, or how Velto works internally. If you're comfortable with basic Python—functions, imports, and running a script—you have enough to begin. If HTML or JSX looks familiar, PSX Markup will feel familiar too.

## What you'll learn

By the end of this getting-started path, you'll understand how to:

1. **Prepare your Python environment** and install Velto.
2. **Read a PSX Markup interface** using tags, attributes, and nested elements.
3. **Run a working example** and see what Velto creates.
4. **Open a native desktop interface** using a supported renderer.
5. **Choose what to learn next**, from components and events to state and layout.

You won't need to memorize the framework's architecture before writing your first line of markup.

## First, get a feel for PSX Markup

Velto lets you express an interface with markup inspired by HTML and JSX.

```python
from psx import psx

view = psx("""
    <Flex direction="column" gap="12">
        <Text>Hello, Velto!</Text>
        <Button>Get started</Button>
    </Flex>
""")
```

Read this from the outside in:

- `Flex` is the parent layout container.
- `direction="column"` tells the layout to arrange its children vertically.
- `gap="12"` describes the spacing between those children.
- `Text` and `Button` are two elements inside that container.

That's the central idea: **describe the structure of your interface using readable tags**. Velto processes the resulting interface tree and can render it through a native Python UI toolkit.

<Note>
  This snippet demonstrates the appearance of PSX Markup. It is not a complete application and does not open a window on its own. The linked tutorials provide complete source files and the commands needed to run them.
</Note>

## Why does the first example run in a terminal?

Velto supports a **Headless renderer** as well as native renderers.

Headless is useful for learning and testing because it builds an inspectable interface tree **without opening a window**. That makes it easy to confirm that a component produced the expected result.

A native renderer takes the next step: it creates widgets through a desktop toolkit such as Tkinter or Qt. Both approaches use Velto's UI concepts, but only the native renderer creates a graphical window.

You'll encounter both in this guide, in that order, so each new concept has a clear purpose.
