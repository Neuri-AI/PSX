## Precision decision and actual implementation

**D-F1.11:** 0.01 logical px pure / 1.0 logical px native; exact tree IDs/order/flex lines. A single Blink LayoutUnit is **1/64 = 0.015625 logical px**, which **exceeds 0.01**. The original fuzz failures were incorrect **border widths** as well as subsequent x positions. Rounding final sanitized boxes is prohibited because it cannot repair an allocation error that already propagates to later children.

Reference oracle, from actual [Chromium CI 38103899275](https://github.com/Neuri-AI/PSX/actions/runs/38103899275): **Playwright 1.63.0**, Chrome for Testing / Chromium Headless Shell **153.0.8010.12**, Playwright build **1243**, Ubuntu x86_64, device-scale-factor 1. `tests/sfle/fixtures/f2_alpha_acceptance.json:chromium_reference` pins the oracle and `test_sfle_chromium_version.py` checks the launched `browser.version` before geometry tests. The Chromium workflow pins `playwright==1.63.0` and runs this mandatory test. Upgrading requires recalculating and reviewing affected DOM fixtures first; it may not silently advance on a dependency upgrade.

**Actual arithmetic, do not overclaim:** Python (`compute_alpha.py`) and Rust (`compute_layout.rs`) apply corresponding 1/64 px quantization to applicable resolved percentages and used main sizes, and `margin_tree.py`/`margin_tree.rs` quantize each relevant placement/translation increment. Explicit percent `flex-basis` is floored to the 1/64 grid *before* the flexible-length loop; percentages on other properties use applicable resolution stages. The flexible-length freeze/allocation loop itself is **f64**, not a full integer-based implementation of Chromium's `LayoutUnit` arithmetic. After §9.7 allocation, both engines model reverse-order distribution of the remaining integer subpixel units using CSS flex-factor weights, before recursively laying out children. The prior matched 100-case seed validated this **restricted algorithm**, not general Blink fixed-point equivalence. **The 19 out-of-sample REDs prove remaining rounding divergence**. Do not describe both engines as fully emulating Blink until a broader independent oracle verifies the freezing/remainder ties.

## Orthogonal dimensional RED suites

Each test module contains **eight deterministic generated trees** and was introduced in a separate commit *before implementing these missing capabilities*, using `f2_fuzz_dimension_helpers.py`. The first-line commits are: RTL `2e0cab1d`; reverse `9bc21267`; fixed wrap `7e187a28`; nested columns `11ef1df1`; min/max `28788334`; alignments `3ba7835a`; margins `835915d0`. The shared helper compares IDs and all four *border* axes at 0.01px against actual DOM. No dimension is silently marked supported because it raised an unsupported exception.

- **RTL:** horizontal row writing direction RTL with fixed basis/size/gap — initial 8/8 passed in [browser 38104644630](https://github.com/Neuri-AI/PSX/actions/runs/38104644630); this does not cover all RTL combinations or wrap.
- **Reverse:** generated row-reverse and column-reverse with fixed dimensions. The initial run exposed six mismatches caused by a **test-generated CSS gap/reference mismatch**; after setting `row_gap` as well as `column_gap` for the column main axis, **8/8 passed** in [browser 38104890520](https://github.com/Neuri-AI/PSX/actions/runs/38104890520). This is fixture equivalence, not an engine bug silently waived.
- **Wrap fixed:** `wrap` for a definite-width row — all eight currently RED on unimplemented style semantics; line IDs and membership not yet certified.
- **Nested columns:** fixed-size row with nested column and two descendants including width 100% — **8/8 passed** in [browser 38104890520](https://github.com/Neuri-AI/PSX/actions/runs/38104890520) as numeric synthetic trees; **not** a real multiline text/intrinsic convergence proof.
- **Min/max:** bounded max-width alongside flex sizing — all eight currently RED due unimplemented normalized style; must implement both engines.
- **Alignments:** `justify_content:space-between` — all eight currently RED due unimplemented normalized style.
- **Margins:** per-item `layout_margin_left` — all eight currently RED due unimplemented normalized style.

**Covered by the holdout:** row, LTR, nowrap, fixed/indefinite containing width, mixed px/percent/auto basis, grow/shrink, gaps, padding, 1–5 items. **Not covered by the holdout:** RTL, reverse, wrap, nesting, min/max, alignments, margins. The seven independent suites test those dimensions; they must not be silently added to the holdout as automatic unsupported PASS.

## Qt, lifecycle, other renderers and build matrix — no omitted blockers

1. **Qt worker thread adjustment — PARTIAL:** `test_f2_qt_worker_ui_thread_red.py` proves synchronous wrong-thread measurement is rejected; `test_f2_qt_worker_async_red.py` proves the dispatcher can send measurement and commit to UI while processing event-loop heartbeats. It does **not** yet prove the full *production* renderer scheduler chooses worker-only pure compute on a separate OS thread and UI-thread-only native operations under all generation races. Add explicit thread identity, positive worker propagation and lifecycle integration assertions.
2. **Qt stable font / relation adjustment — PARTIAL:** A04 Qt real-wrap test requests DejaVu Sans Mono, 10-pixel font and asserts 100→150px measurements and a relative wrap-height reduction. Async worker test uses `QApplication.font()` without pinning or checking an actually resolved family. Specify a guaranteed available fixture font or reliable font-independent relation for **both** real and worker tests; record font/DPI revision and avoid assuming one particular Linux host font.
3. **Qt `geometry_commit_error` ≤1.0 px adjustment — PARTIAL:** `test_f2_a04_qt_real_wrap_red.py` asserts a returned error around 0 with ±1 and checks label geometry; need a direct independent observation of all committed x/y/width/height and assert `0 <= geometry_commit_error <= 1.0` (plus separately reported measurement/engine errors). No fictitious 0 when not observed.
4. **Cycle classification inversion — FAIL:** N01–N05/C99 prove only named rejections; `compute_alpha.py` and `compute_layout.rs` still implement structural shortcuts and a partial allowlist. Unsupported graphs must default to explicit failure, not implicit auto/zero or acceptance. Preserve valid indefinite percentage semantics via the CSS-spec-defined allowlist; prove negative fuzz classes.
5. **Kivy — NO END-TO-END PROOF:** `kivy_measurement.py` and unit tests probe texture metrics. No full UI-thread native remeasure → immutable snapshot → selected Rust/Python → generation guard → native commit → per-channel error test.
6. **Tkinter — NO END-TO-END PROOF:** `tk_measurement.py` and thread-affinity/unit tests exist. No full scheduler/native geometry equivalence or click/scroll stability certification.
7. **Headless — NO END-TO-END PROOF:** `headless_measurement.py` has fixture-level metrics, but no fully wired production Headless renderer consuming the same current-generation SFLE result as Chromium.
8. **Windows/macOS wheels — NO CI PROOF:** Existing `sfle-core.yml` builds/installs Linux PyO3/maturin only. Add Windows and macOS build/install/cross-backend parity, source installs without compiler and Qyro/PyInstaller frozen import with/without binary; preserve load-time-only fallback. Linux-only GREEN does not certify distribution.
